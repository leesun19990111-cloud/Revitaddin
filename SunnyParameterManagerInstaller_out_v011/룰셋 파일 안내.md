# 룰셋 파일 안내

규칙은 프로그램 안에서 만들지 않습니다. 사용자와 대화로 정한 내용을 **.sunnyrules.json** 파일로 만들어 전달하고, 프로그램에서는 **RVT 파일 선택 → 룰셋 불러오기 → 변경 내용 확인 → RVT에 저장**만 수행합니다.

업무 규칙은 아직 정하지 않았습니다. 함께 들어 있는 **연습용.sunnyrules.json**은 **샘플로 연습하기**에서만 쓸 수 있고 실제 모델에는 적용할 수 없습니다. 샘플을 연 뒤 이 파일을 불러오면 두 샘플 파일의 업체명 36개가 어떻게 바뀔지 표시됩니다. 실제 저장은 비활성 상태입니다.

## 룰셋 작성자를 위한 형식 (사용자가 직접 편집할 필요 없음)

- UTF-8 JSON, 최대 2MB. Version: 1, Name, Rules 필수. SampleOnly: true면 연습 데이터에서만 사용.
- 규칙마다 고유한 Name, Match, Set을 지정. 최대 500개 규칙, 규칙당 100개 입력값.
- Match.Scope: 유형, 인스턴스, 프로젝트 정보 중 하나. 유형/인스턴스는 Type 조건 필수.
- Match.TypeMatch: 일치(기본), 시작, 포함. 대소문자를 구분하며 와일드카드/정규식/실행 코드는 없음.
- Match.Model, Category, Family: 선택 사항. 조회된 모델 제목(확장자 없는 이름)·카테고리·패밀리에 정확히 일치. 지정된 조건은 모두 만족해야 함. 모델 제목이 같으면 해당 제목의 파일 모두 대상이므로 최종 목록에서 소속 파일 확인.
- Set: Name, DataType, Storage, Value 필수. 자료형은 추측하지 말고 실제 조회값의 식별자를 사용. Storage는 String, Integer, Double, ElementId.
- ParameterKey를 지정할 때는 guid:<공유 GUID> 또는 builtin:<음수 ID>만 허용. 다른 모델에 의미가 다른 id:는 금지. 지정 시 이름·자료형·저장형식·키가 모두 맞아야 함. 미지정 시 **각 소유 요소 안에서** 이름·자료형·저장형식이 유일한 항목만 연결. 모델 간 현재값 자동 복사와 달리 명시한 고정값을 입력하는 규칙임.
- Value는 문자열. 빈 문자열은 텍스트 지우기, 누락/null은 오류. 숫자 "25", 치수 "200 mm", 선택형은 해당 모델 선택 목록의 정확한 이름을 사용. 단위 숫자 해석은 실제 적용 시 Revit에서 재검증.
- 공유 GUID/자료형 등 룰셋 작성에 필요한 실제 메타데이터는 **연결 설정 · 작업 보관 → 작업 저장**의 조회 결과에서 확인 가능. 작업 파일에는 실제 프로젝트 정보가 있으므로 외부 공유 주의.

## 범위와 안전

룰셋은 **조회가 완료된 등록 파일 전체**를 대상으로 합니다. 목록의 검색어, 보이는 필드, 선택 행은 룰셋 범위를 제한하지 않습니다. 파일별로 다르게 적용하려면 룰셋 조건에 모델명을 명시하거나 대상 파일만 등록합니다.

조건에 맞는 대상이 없는 규칙은 미리보기 위에 표시합니다. 대상은 있으나 매개변수가 없거나 여러 개이거나 읽기 전용인 경우, 잘못된 입력값 또는 서로 다른 규칙/기존 변경값의 충돌은 **룰셋 전체를 보류**합니다. 기존 변경 목록을 지우거나 마지막 규칙으로 몰래 덮어쓰지 않습니다.

동일한 값은 변경 목록에서 제외합니다. 불러온 결과에는 규칙 이름을 기록합니다. 변경 목록에서 원하지 않는 항목을 제외할 수 있습니다. 불러오기만으로 파일을 열어 수정하거나 저장하지 않습니다. 최종 저장 때 기존값·실제 권한·대상 식별자를 재검증하며 이전 버전의 중앙 동기화 안전장치를 그대로 사용합니다.

룰셋 자체는 중앙 동기화의 성공이나 Revit 네이티브 오류 부재를 보장하지 않습니다. 처음에는 별도 테스트 모델에서 검증하세요.
