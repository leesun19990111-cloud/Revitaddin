# v105 링크 편집 강제 종료 분석 및 예방

## 확인된 사실과 한계

2026-10-14 사용자가 보고한 Revit 2026.4 강제 종료에 대해 이 PC의 저널을 읽기 전용으로 조사했다. 운영 모델을 열거나 저장·동기화해 재현하지 않았다.

| 저널 | 마지막 오류 시각 | 공통 경로 |
|---|---|---|
| journal.0239 | 09:45:14 | 링크 해제 후 임시 로컬 로드 → SelectedPartitionsForEdit → decommitDocument → 0xc0000005 |
| journal.0240 | 10:59:16 | 동일 |
| journal.0241 | 11:01:27 | 동일 |

모두 애드인이 만든 `LinkedModelEdits` 임시 로컬을 `OpenDocumentFile`로 읽는 도중이다. 이 실행의 편집/중앙 동기화 단계까지 도달하지 않았다. `DSI::loadPermissionsFiles` 메시지만으로 서버 권한을 원인으로 단정할 수 없다. 모델 데이터·작업세트·Revit 엔진·다른 애드인 중 어떤 내부 조건이 접근 위반을 만들었는지까지는 네이티브 덤프 분석 없이는 확정할 수 없다. 원본 저널과 덤프에는 프로젝트/서버 정보가 있으므로 공개 저장소에 포함하지 않는다.

## 적용한 방어

1. **자동 문서 수명 변경 제거:** 새 로컬 생성, 링크 해제, 원본 재열기, 자동 닫기/재로드를 공통 링크 편집 경로에서 삭제했다. 실행 옵션으로 다시 활성화할 수 없다. 같은 Revit에 이미 열린 정상 원본/로컬만 수정한다.
2. **전체 사전 검사:** NAMER·재료 지정·일람표 에디터에서 변경할 모델 전체의 준비 상태를 먼저 확인한다. 변경하지 않는 링크는 검사 대상이 아니다. 준비 부족이면 이번 일괄 작업은 아무 모델에도 쓰지 않는다.
3. **기존 작업 보호:** 기존 미저장/미동기화 작업도 함께 중앙으로 반영된다는 기본 ‘아니요’ 확인을 유지한다. 기존 소유권을 일괄 반환하지 않는다. 트랜잭션 그룹이 종료된 뒤에만 동기화한다. [Autodesk 동기화 API 제약](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/7de73a7b-68f0-87f2-f6a9-97d824024877.htm).
4. **실패 정책:** 적용 실패는 해당 그룹 롤백. 동기화 실패는 중앙 반영 여부 미확정으로 보고하고 열린 문서의 변경을 보존한다. 자동 재시도·저장·닫기 없이 남은 모델 중단. 성공한 이전 중앙까지 되돌리지는 못한다. 현재 모델은 반영만 하고 자동 동기화하지 않는다.
5. **진단/회귀 방지:** 중첩 실행 거부. 로컬 Diagnostics에 작업 식별자·시각·단계만 기록하며 개인정보/모델 경로/값은 기록하지 않는다. 설치 파일 검증에서 위험 API의 재유입을 검사한다.

## 사용자 작업 순서

- Revit을 모두 종료한 뒤 v105 설치 파일을 사용한다. 이전 실행에서 링크가 내려간 채 남았다면 호스트의 링크 관리 상태를 확인한다. 새 버전이 이전 세션의 링크 상태를 임의 복원하지 않는다.
- **변경할 링크 중앙의 로컬을 같은 Revit 창/세션에 일반 파일 열기로 먼저 연다.** 다른 PC나 다른 Revit 프로세스에서 열린 것은 이 조건을 만족하지 않는다. 중앙과 그 로컬을 동시에 열라는 뜻도 아니다. 중앙에서 분리한 사본은 동기화 대상이 아니다.
- 호스트로 돌아와 NAMER/재료 지정/일람표 에디터에서 조회 후 변경한다. 대상 원본의 기존 작업도 함께 동기화한다는 안내를 확인한다. 운영 모델로 즉시 대량 작업하지 말고 아래 별도 테스트를 먼저 수행한다.
- 성공 후 중앙 반영과 호스트 링크 화면 갱신은 별개다. 필요할 때 사용자가 링크 관리에서 갱신한다. 다른 사용자의 로컬은 그 사용자가 최신 항목을 불러와야 한다.

## 자동 검증 결과

- link-safety-v105: 52개. 실제 서비스 + API 대역. 원본 부재/잘못된 상태/변경 경로 차단, 확인 취소, 그룹 종료 후 Sync, 중첩 실행, 오류 후 가드 해제, 실패 변경·문서·소유권 보존. 폐기된 자동 새 로컬 테스트를 새로운 차단 정책으로 대체했다.
- unified-v105: 221개. 기존 213개 + 8개 전체 사전검사 회귀. 뒤 링크 부재 시 앞 링크/현재 모델 미변경, 변경하지 않는 링크 제외, 실제 명령의 쓰기 전 차단, 경로·읽기 전용 검사.
- release-v105: 기존 91개 네이머/재료/복합 구조 보존 회귀.
- Revit 2023~2027 격리 빌드 오류 0. 설치기 30파일의 원본/Payload/ZIP 해시 일치. 모든 연도에서 Clipper 포함, Autodesk DLL 제외. 배포 DLL에서 CreateNewLocal/OpenDocumentFile/UnloadLocally/RevertLocalUnloadStatus/RelinquishOwnership 부재 확인.

대역 검증은 실제 Revit의 네이티브 동작과 서버 소유권 검증을 대신하지 않는다. 따라서 이번 버전은 **확인된 충돌 유발 경로 제거 및 방어 강화**이며 모든 강제 종료가 재발하지 않는다는 보증이 아니다.

## 실제 Revit에서 남은 검증

운영 중앙에 연결되지 않은 별도 테스트 중앙 A/B와 테스트 호스트를 준비한다. 운영 모델의 로컬을 단순 복사한 것은 안전한 테스트가 아니다.

1. 원본 A/B를 열지 않고 현재+A+B 변경 시도: 아무 모델도 변경하지 않고 필요한 모델을 안내해야 한다. 새 임시 로컬/링크 해제가 없어야 한다.
2. A만 열고 B는 닫은 경우: 뒤 B 때문에 사전 중단하며 A/현재 모델에도 변경이 없어야 한다. 현재 모델만 변경하면 B를 열지 않아도 가능해야 한다.
3. A/B의 정상 로컬을 열고 A에 기존 미동기화 테스트 변경을 남긴다. 확인 ‘아니요’는 기존 변경을 보존하고 작업을 중단해야 한다.
4. 이름 1개/재료 1개/일람표 값 1개부터 각각 시험한다. 중앙 동기화 후 별도 테스트 로컬에서 실제 값을 확인한다. 열린 문서/소유권 유지, 링크 해제·재로드 없음, 구조 재료/가변/기능/두께 불변을 확인한다.
5. 잠금 충돌/테스트 네트워크 장애에서는 자동 재시도 없이 중단, 중앙 반영 여부 미확정 안내와 열린 문서 변경 보존을 확인한다. 중앙 상태 확인 전 무작정 다시 실행하지 않는다.
6. 일반 Revit 파일 열기나 이 열린 원본 경로에서도 강제 종료하면 즉시 중단한다. 해당 저널/덤프와 `%LOCALAPPDATA%/WallSplitter/Diagnostics/LinkedEdit-yyyyMMdd.log`를 로컬에서 함께 조사한다. 공개 저장소/게시판에 원본 프로젝트 경로가 들어간 자료를 그대로 올리지 않는다.
