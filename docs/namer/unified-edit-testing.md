# 통합 모델 편집 라이브 검증 (v98)

자동 검사는 실제 Revit 서버 동기화를 대신하지 않는다. 아래 검증은 사용자가 별도 테스트 중앙모델에서 수행한다.

1. 운영 중앙과 연결되지 않은 테스트 중앙 A/B와, 그 중앙을 링크한 테스트 호스트를 준비한다. 운영 중앙의 로컬만 복사해 사용하는 것은 안전한 테스트가 아니다.
2. Revit 종료 후 새 설치본을 설치하고 테스트 호스트의 새 로컬을 연다. 첫 저장 전에도 통합 조회가 가능해야 한다.
3. NAMER에서 현재/A/B의 같은 이름 요소가 모델별로 따로 보이는지 확인한다. 동일 링크를 두 번 배치해도 원본 요소는 한 번만 보여야 한다.
4. 패밀리 검색, 하위 유형 펼침, 하위 유형만 선택, 다른 모델 유형 동시 선택, 직접 입력/문자열 치환을 시험한다. 최종 적용 전에 취소했을 때 모델이 바뀌지 않아야 한다.
5. 최종 적용 확인창에서 모델별 건수와 원본 경로를 확인한다. A/B 동기화 후 링크가 복원되는지, 현재 모델은 반영만 되고 저장/중앙 동기화는 직접 해야 하는지 확인한다.
6. 재료 지정에서 모델별 재료를 각각 선택한다. 동일 유형의 다른 인스턴스 재료는 다양함이며 해당 그룹 전체에 적용돼야 한다. 구조 재료·가변·기능·우선순위·두께·코어는 그대로인지 비교한다.
7. 다른 테스트 사용자의 소유권 충돌이나 테스트 환경의 연결 장애를 시험한다. 앞선 성공 모델, 실패 모델, 남은 미처리 모델을 구분하고 자동 재시도하지 않는지 확인한다. 동기화 중 장애는 중앙 반영 상태를 먼저 확인한다.
8. 미로드/중첩/다른 버전/클라우드 링크의 제외 사유가 표시되는지 확인한다. 조회값 이후 변경된 요소·재료·인스턴스 범위는 덮어쓰지 말고 재조회하도록 안내해야 한다.
9. 현재 모델 전용 도구의 기존 모드리스 NAMER/특성 및 재료 삭제/클래스·설명 기능이 유지되는지 확인한다.
10. 통합 창의 검색·변경 구역이 분리되고 열 경계 드래그 시 머리글/행 너비가 같이 바뀌는지 확인한다. 행을 빠르게 끌거나 되짚어도 누락/반전 없이 선택되며 Shift 범위 선택, 하위 유형 체크 집계가 맞는지 본다.
11. 선택 후 치환값을 타이핑할 때 우측 예시 이름이 즉시 바뀌는지 확인한다. 창 안 적용 전에는 누적 변경이 늘어나지 않아야 한다. 더블클릭 편집/Enter/Esc/다른 곳 클릭 및 창 안 적용 뒤 페이지·스크롤 보존을 확인한다.
12. 파일 기반 로컬에서 ‘현재 프로젝트도 파일 기반 중앙모델의 로컬이어야 합니다’로 잘못 차단되지 않는지 확인한다. 링크를 다시 로드하고 별도 테스트 로컬에서 최신 작업 다시 로드로 **중앙 원본의 실제 이름 변경**을 확인한다. 단지 임시 로컬 파일이 저장되었다는 사실은 성공 근거가 아니다.

**주의:** 링크 해제·갱신은 현재 모델 실행 취소 기록에 영향을 줄 수 있다. 이미 동기화된 여러 중앙모델을 호스트의 실행 취소로 일괄 되돌릴 수 없다. 실패 후 보존된 전용 로컬은 자동 동기화하지 말고 중앙의 실제 상태와 먼저 비교한다.
