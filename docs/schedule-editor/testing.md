# 일람표 에디터 테스트 순서

## v107 다중 카테고리 / 사용자 매개변수 / IFC

아래는 자동 검증 결과가 아닌 **아직 필요한 실제 Revit 검증**이다. Revit 종료 후 v107 설치. 운영 중앙과 분리된 테스트 중앙/호스트를 사용하고 수정할 링크 로컬을 같은 Revit에 먼저 연다.

1. 다중 카테고리 일람표에 재료명·층·업체명·조달청표준공사코드·건축물번호를 넣고 링크 포함을 켠다. 같은 값을 가진 현재 모델/두 링크의 행이 모델별로 구분되는지 확인한다. 원본 일람표의 정렬/필터/열/서식은 조회 후 그대로여야 한다.
2. 한 링크의 구분되는 행만 선택해 업체명을 변경한다. 다른 모델/미선택 요소는 그대로이고, 중앙 동기화 후 다른 테스트 로컬의 최신 항목 다시 로드에서 값이 확인되어야 한다.
3. 같은 모델의 완전히 동일한 두 행은 `공동 N`과 함께 선택 필요가 표시되어야 한다. 하나만 선택해 적용하면 변경 없음. `동일 표시 행 함께 선택` 후 적용하면 확인된 공동 대상 전체만 변경한다. 반올림 원시값 차이/개수 불일치/비개별 중복 그룹은 여전히 차단한다.
4. 비공유 프로젝트 매개변수를 모델마다 독립 생성해 내부 ID가 다르게 한다. 행/필드 선택 → `프로젝트 매개변수 연결 확인`의 이름·자료형·모델·유형/인스턴스·ID 확인. 기본 아니요/취소면 적용 차단, 승인하면 정확한 원본 ID만 변경. 동명 후보가 여러 개거나 자료형이 다르면 연결하지 않아야 한다. 공유 매개변수는 GUID 연결로 이 승인 없이 편집되어야 한다.
5. 열린 원본에서 이미 값을 바꾼 경우 링크의 옛 값으로 덮어쓰지 않는지 확인한다. 원본 동기화/호스트 링크 갱신은 사용자 조작으로 하고 다시 조회한다. 값 삭제·유형 교체·필터 조건 변경도 저장 전에 차단되어야 한다.
6. `다음으로 IFC로 내보내기`를 선택해 `IfcWall` 등 해당 요소에 적절한 엔티티명을 입력한다. 원본 특성 값과 중앙 반영을 확인한다. 내보내기 여부/유형/미리 정의된 유형은 자동 변경되지 않아야 한다. 별도로 선택한 IFC 스키마로 내보내 엔티티를 확인한다. 이 기능은 IFC 스키마 선택기나 검증된 클래스 목록을 제공하지 않는다.
7. 실제 읽기 전용/수식/지원하지 않는 관련 요소 필드는 여전히 차단되어야 한다. 드래그·Shift·범위 입력 및 기존 형식별 입력기를 함께 확인한다. Revit 2023 일반 요소 링크 포함은 기존 미지원 안내를 유지한다.

## v105 공통 링크 안전 경로

수정할 링크 중앙의 정상 로컬을 같은 Revit에 먼저 열어 둔다. 애드인의 임시 로컬 자동 재열기는 제거됐다. 원본을 하나라도 열지 않은 경우 현재 모델 포함 모든 변경 전에 사전 차단하는지, 열린 원본의 기존 작업 포함 확인/동기화 실패 변경 보존을 확인한다. [v105 분석과 별도 테스트 중앙 검증 절차](../namer/linked-edit-crash-v105.md)를 우선 적용한다.

## v103 도면목록표 추가 확인

Revit 종료 → v103 설치 → 재시작. 아래 실모델 확인은 운영 중앙과 연결되지 않은 테스트 모델에서 한다. API 대역 자동 검사를 통과했지만 실제 Revit/서버 검증 완료를 의미하지 않는다.

1. 현재 모델과 링크 두 개에 동일 도면번호(A01-001 등)를 준비한다. 링크 포함 도면목록표의 실제 행 순서·소속 모델·도면번호/도면명 편집 가능 상태를 확인한다. 한 링크의 한 행만 수정해 다른 모델의 동명 시트는 그대로인지 확인한다.
2. 링크 포함을 끄고 비어 있는 `RVT 링크: 파일 이름` 열을 남긴다. 그 열은 읽기 전용이되 도면번호·도면명을 선택하면 편집 입력과 미리보기에 적용이 활성화되어야 한다.
3. 도면번호를 숨기거나 표시 열에서 빼고 재조회한다. 도면명 등 일반 필드는 계속 연결되어야 하며 조회 후 원본 일람표에는 보조 열이 추가되거나 숨김/서식/정렬이 바뀌면 안 된다.
4. 다른 경로에 같은 파일 이름/같은 도면번호·이름이 있는 경우 모호한 행만 차단하는지 확인한다. 같은 원본을 여러 번 링크한 경우 실제 시트는 한 번만 변경되어야 한다.
5. 도면명 기준으로 여러 시트를 묶은 행은 실제 개수와 대상 전체가 맞을 때만 수정 가능해야 한다. 필터로 일부를 제외하여 정확한 대응을 확인할 수 없으면 추측하지 않아야 한다.
6. 같은 Revit의 열린 링크 원본에 미동기화 도면명 변경이 있으면 표의 옛값을 다시 덮어쓰지 않아야 한다. 중앙 반영 확인은 아래 기존 안전 절차로 검증한다. 기존 미동기화 작업도 포함될 수 있다는 확인창은 유지한다.
7. 2023~2027 각각 도면목록표 전용 경로를 확인한다. 2023의 일반 모델 요소 링크 포함 일람표는 여전히 제한하며 모든 종류의 링크 일람표 지원으로 해석하지 않는다.

## v102 필드별 편집 추가 확인

운영 모델이 아닌 별도 테스트 모델에서 Revit 종료 → v102 설치 → 재시작 후 진행한다.

1. 텍스트 없이 서로 다른 숫자만 표시한 일람표, 길이/면적/각도/단위 없는 숫자, 사용자 지정 단위·반올림 서식을 각각 확인한다. 원래 정렬 순서·값·대상 요소가 일치해야 한다. 표시가 같아지는 서로 다른 원시값은 읽기 전용으로 차단돼야 한다.
2. 숫자/레벨 기준 묶인 행을 확인한다. 요소 수와 전체 수정 범위가 맞아야 한다. 계산식/관련 요소 기준 정렬이나 식별 불가 목록은 창은 열되 수정 불가 사유를 표시해야 한다.
3. 텍스트/정수/실수/예 아니요 필드를 차례로 선택한다. 각 입력 방식이 달라지고 이전 필드의 입력값은 새 필드로 넘어가지 않아야 한다. 정수에 소수, 숫자에 빈값은 미리보기 차단. 잘못된 숫자 문법/단위는 최종 적용 실패 및 해당 모델의 변경/로그 전체 취소를 확인한다.
4. 재료/지원 레벨은 소속 모델별 이름 검색 → 목록에서 직접 선택한다. 검색만으로 지정되지 않아야 한다. 선택한 행이 여러 모델이면 모두 명시 선택해야 한다. 같은 이름의 다른 모델 항목은 자동 연결되면 안 된다. 레벨 변경 시 실제 위치/높이 영향도 확인한다.
5. 계산식/합성/합계/읽기 전용/지원하지 않는 전용 참조·열거 필드는 읽기 전용 표시, 지정 버튼 비활성. 이 필드가 함께 있어도 안전하게 대응된 다른 직접 필드는 편집할 수 있어야 한다.
6. 참조 선택 후 해당 재료/레벨을 이름 변경 또는 삭제한 경우 재조회 안내, 실제 값 보존 확인. 음수 sentinel(없음/카테고리별/연결 안 됨)은 이번 버전에서 새로 선택하지 않으며 원래 값은 지정하지 않으면 그대로 유지된다.
7. 두 모델의 프로젝트 단위가 다르면 숫자 입력 안내와 적용값을 비교한다. 단위 생략 시 각 모델의 단위, 명시하면 그 단위로 해석해야 한다. 링크 중앙 안전 확인은 아래 기존 절차를 계속 수행한다.

## v101 범위 선택 추가 확인

1. Revit을 종료하고 v101 설치 후 테스트 일람표를 연다. 미체크 3행에서 8행까지 드래그한 뒤 5행으로 되짚어도 3~8행이 모두 체크돼 있어야 한다.
2. 체크된 5행에서 7행으로 드래그하면 그 범위만 해제돼야 한다. 이어서 미체크 행에 Shift + 클릭하면 마지막 클릭 행부터 범위 선택, 체크된 행에 Shift + 클릭하면 범위 해제되는지 확인한다.
3. 행 번호 `2,4-6,250-260` 직접 입력과 체크 상태가 일치하는지 확인한다. `1-` 등 잘못된 입력은 오류 표시·선택 해제되며 적용할 수 없어야 한다. 행을 다시 클릭하면 유효한 범위로 바뀐다.
4. 200행 더 보기, 필드 변경, 미리보기 적용 뒤 선택·펼친 페이지·스크롤을 확인한다. 마지막 클릭 행과 Shift 클릭 행 사이가 200행 경계를 넘어도 중간 행이 빠지지 않아야 한다.
5. 드래그 중 목록 위/아래 끝에 커서를 두면 자동 스크롤, 창 밖에서 마우스를 놓거나 다른 창으로 전환하면 종료되는지 확인한다. 이후 마우스 이동만으로 체크가 바뀌면 안 된다. 헤더 열 너비 조절·입력창·더 보기 버튼은 행 드래그를 시작하지 않아야 한다.
6. Tab으로 체크박스에 이동해 Space로 체크·해제하는지 확인한다. 일부 값을 미리보기 적용한 뒤 체크를 해제해도 누적 변경은 보존돼야 한다. 체크만 변경하고 닫으면 실제 모델은 바뀌지 않아야 한다.

## 기존 데이터/중앙 동기화 검증

운영 중앙과 연결되지 않은 **별도 테스트 중앙과 호스트**에서 실행한다. 운영 모델 로컬을 단순 복사한 것은 안전한 테스트 모델이 아니다.

1. Revit 종료 → v100 설치 → 재실행. NAMER 패널의 `일람표 에디터`를 확인.
2. 마크가 `A-01`, `A-02`, `B-01`인 요소 일람표를 만들고 역순 정렬. 마크·주석을 표시한다. 에디터의 1행이 Revit 정렬의 첫 데이터 행인지 비교한다. 제목/소계/빈 행은 번호에서 제외.
3. 필드 `주석`, 행 `1-2`, 값 `시험` → 미리보기 적용. 나머지 행은 그대로인지 확인. 닫기만 하면 실제 모델은 변하지 않아야 한다.
4. 최종 적용 후 요소 특성의 주석을 확인. 현재 모델은 아직 자동 저장/중앙 동기화되지 않아야 한다.
5. 텍스트 마크 기준 그룹으로 바꾸고 같은 마크 3개를 한 행으로 표시. 개수가 3인지 보고 해당 행을 수정하면 정확히 3개에 적용되어야 한다. 숨긴 정렬 필드, 합계/소계/빈 구분행을 추가해도 같아야 한다. 원본 일람표의 필드/템플릿/서식/정렬은 변하지 않아야 한다.
6. 개별 행이 같은 텍스트 값만 가지면 v107의 공동 대상 전체 선택 규칙을 따른다. 하나만 임의 요소에 연결해서는 안 된다. 고유한 마크를 표시하면 개별 수정이 가능해야 한다. 숫자/레벨 기준 그룹은 v102 절차로 확인하고 계산식/합계 표시 필드는 직접 편집하지 않아야 한다.
7. 유형 매개변수 수정 시 같은 유형의 다른 행에도 미리보기가 표시되는지 확인. 선택 밖 인스턴스까지 영향을 받는다는 안내를 확인한다. 원하지 않으면 적용하지 않는다.
8. 링크 포함 일람표(Revit 2024~2027)에 같은 ID/다른 소속 요소를 배치. 해당 링크 행만 수정해 중앙의 실제 특성을 확인한다. 호스트의 같은 ID 요소는 그대로여야 한다. 사용자 정의 필드는 공유 매개변수로 시험한다.
9. 같은 Revit에 대상 중앙/로컬을 별도로 열어 미동기화 시험 작업을 남긴다. 추가 확인에서 아니요 → 모두 그대로. 예 → 기존 작업+일람표 변경 중앙 반영, 열린 문서/소유권 유지. 다른 테스트 사용자 로컬의 최신 항목 다시 로드에서 확인한다.
10. 조회 이후 원본 값/정렬 조건/유형을 변경한 경우 덮어쓰기 차단. 잠금·읽기 전용·동기화 실패 시 모델별 실패/미처리, 복구 안내를 확인한다. 중앙 상태 확인 전 자동 재시도하지 않는다.
11. NAMER `프로젝트 정보`: 빈 항목 `없음`, 실제 0/아니요는 정상 표시, 동명 매개변수 분리, 직접 입력/삭제/여러 항목 지정. 현재 모델 전용/통합 양쪽에서 확인. 읽기 전용 값은 그대로.
12. 재료 지정: 모델별 검색칸에 한국어/영어 일부 입력 → 직접 선택. 검색 결과가 바뀌어 선택이 제외되면 지정이 해제되고 다른 모델의 선택은 유지. 구조 재료/가변/우선순위는 변하지 않아야 한다.
