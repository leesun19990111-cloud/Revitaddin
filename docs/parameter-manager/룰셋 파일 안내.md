# 룰셋 파일 안내

## 읽기 전용 KAC 재료 점검 (버전6, 프로그램 0.3.8 이상)

`{"Version":6,"Name":"KAC 재료 유형·인스턴스 점검","SampleOnly":false,"Rules":[],"MaterialAudit":true}` 형식입니다. 다른 변경 규칙·정리 프로필과 혼합할 수 없습니다. 룰셋을 먼저 고르고 RVT를 새로 조회하면 실제 배치된 요소의 유형 재료 매개변수·복합구조 층·형상과 배치 요소의 인스턴스 재료 매개변수·형상·페인트를 읽습니다. 인스턴스 재료 슬롯과 `KAC-` 이외 실제 재료 사용을 모델/유형별 XLSX로 정리하며 현재 재료명도 표시합니다. 0.4.0부터 선택한 룰셋과 같은 폴더의 `KAC_재료_유형인스턴스_점검결과.xlsx` 한 파일을 갱신합니다. 적용·저장·중앙 동기화는 실행하지 않습니다. 개인 점검 룰셋과 결과 파일은 설치 ZIP·Git에 포함하지 않습니다.

## 안전 삭제 전용 (버전5, 프로그램 0.3.7 이상)

일반 규격 정리와 별도입니다. `Spec.RemoveOnly=true`, `RemovalSafetyVersion=1`, `Parameters=[]`, `AddMissing=false`, `MergeDuplicates=false`를 지정하고 `RemovalTargets`에 정확한 `Name`, 선택적인 `KeepName`, `Categories:["OST_ProjectInformation"]`를 넣습니다. 프로젝트 정보 단독 카테고리만 허용하며 공백·대소문자 정규화로 삭제 대상을 확대하지 않습니다. 남길 이름을 지정하면 그 이름의 정의가 유일하고 프로젝트 정보에 연결되어 있어야 합니다. 값은 이동하지 않습니다.

예: `{"Name":"건축물 번호","KeepName":"건축물번호","Categories":["OST_ProjectInformation"]}`, `{"Name":"구조","Categories":["OST_ProjectInformation"]}`. 개인 업무 룰셋은 설치 파일과 별도로 전달합니다. 이전 버전은 새 안전검증 속성을 거부하며, 0.3.7도 이전 안전근거 없는 삭제 룰셋을 거부합니다. 새 룰셋으로 재조회하고 이전 변경을 섞지 마세요. 일반 버전5 규격 룰셋과 버전1~4 업무 규칙은 기존 형식을 유지합니다.

규칙은 프로그램 안에서 만들지 않습니다. 사용자와 대화로 정한 내용을 **.sunnyrules.json** 파일로 만들어 전달하고, 프로그램에서는 **룰셋 먼저 불러오기 → RVT 파일 선택 → 필요한 항목 조회 → 변경 내용 확인 → RVT에 저장**만 수행합니다.

**0.2.6부터 기존 버전1·KAC 버전2·SP/SA 프로젝트 정보 버전3 룰셋을 수정 없이 먼저 불러올 수 있습니다.** 조회 대상 이름/식별자와 판단 근거를 자동으로 골라 읽습니다. 룰셋 없이 시작하면 전체 조회입니다. 선택 조회에 없는 항목은 빈 값이 아니며, 다른 항목이 필요한 룰셋으로 교체할 때는 다시 조회해야 합니다. 룰셋 교체만으로 기존 변경 예정을 버리거나 RVT에 저장하지 않습니다.

함께 들어 있는 **연습용.sunnyrules.json**은 **샘플로 연습하기**에서만 쓸 수 있고 실제 모델에는 적용할 수 없습니다. 샘플을 연 뒤 이 파일을 불러오면 두 샘플 파일의 업체명 36개가 어떻게 바뀔지 표시됩니다. 실제 저장은 비활성 상태입니다. 실무용 KAC 룰셋은 원본 엑셀과 별도로 전달하며 아래 버전2 설명을 따릅니다.

## KAC 건축·구조 룰셋 (버전2, 배치 요소 포함은 프로그램 0.1.5 이상)

- 유형명이 `KAC-A-영문2자숫자4자리` 또는 `KAC-S-영문2자숫자4자리`로 시작해야 합니다. 코드 뒤는 이름 끝 또는 밑줄/하이픈/공백입니다. 다른 공정·이름 형식은 제외합니다.
- 기본은 유형 텍스트 매개변수 6항목입니다. 0.1.7부터 `InstanceFields`에 명시한 6항목 모두 **같은 실제 유형의 모든 배치 요소에도** 적용할 수 있습니다. 유형에 없는 인스턴스 필드도 입력하고 양쪽에 있으면 각각 입력합니다. 이름이 같은 다른 유형/모델에는 연결하지 않습니다. 매개변수 생성·바인딩 변경·프로젝트 정보 수정은 하지 않습니다. 각 소유 요소에서 유일하고 Revit 텍스트 자료형이어야 합니다. 이전 프로그램은 재료명·업체명·IFC 세 항목만 지원합니다.
- `다음으로 IFC로 내보내기`: IFC 표의 건축 구분에서 유형 코드별 첫 Ifc 이름. 실제 기본 식별자로 유형의 `IFC로 다음 유형 내보내기`, 명시한 경우 인스턴스의 `다음으로 IFC로 내보내기`를 각각 연결합니다. 개별 요소의 기존 IFC 지정도 변경 대상입니다. IFC 내보내기 여부·미리 정의된 유형은 변경하지 않습니다. FA처럼 숫자 분류별로 값이 다르면 구체적인 접두어 우선. IFC 내보내기 파일 자체의 적합성 검증은 별도입니다.
- `제작정보`: KAC-v1.0. `업체명`: ND.
- `KBIMS-부위코드`, `조달청표준공사코드`: 엑셀 항목명으로 열을 찾고 영문 분류+4자리 코드를 정확히 연결합니다. 같은 코드에 다른 값이 있으면 위쪽에서 처음 실제로 적힌 값을 채택합니다. 빈칸은 지우기 명령이 아니며 상위 분류값을 임의로 상속하지 않습니다.
- `재료명`: 벽 외측층, 바닥·지붕 최상단층, 천장 최하단층 재료 이름에서 맨 앞 `KAC-`만 제거합니다. 막층도 건너뛰지 않습니다. 외측층이 미지정이면 안쪽층으로 대체하지 않습니다. 일반 유형은 지정/형상 재료가 하나일 때만 사용하며 여러 재료, 높이별 층 구성이 다른 벽, 미지정 재료는 확인 필요로 둡니다. 수직 복합 속성이 있어도 높이 전체가 일정한 평행층 벽이면 외측 판독을 허용합니다. 인스턴스 재료명도 기준은 유형의 외측 재료이며 도장·인스턴스 재료로 외측을 추정하지 않습니다.
- 미확인/누락/읽기전용 항목은 **그 항목만 기존값 유지**, 검토 요약과 작업 기록에 구체적인 이유를 남깁니다. 이미 준비한 변경과 서로 다른 값을 요구하면 기존 변경을 보존하고 전체 보류합니다. 이 정책은 기존 버전1의 전체 보류 정책을 바꾸지 않습니다.
- **0.1.6의 선택 정책:** Kac에 `UnresolvedMaterialValue: "ND"`를 명시하면 기존 KAC 범위에서 정상 조회했으나 재료 미지정·외측 판별 불가인 항목의 **재료명만 ND**로 대체합니다. 기존 재료명 값도 교체될 수 있습니다. 실제 재료를 찾은 항목은 종전 규칙대로 입력합니다. 다른 5개 항목은 변경하지 않으며 범위 밖의 요소도 추가하지 않습니다. 생략/빈 문자열은 기존값 유지입니다. 임의 대체값은 허용하지 않습니다. API 조회 실패, 구버전 조회 정보 누락, 실제 읽기전용/필드 부재는 ND로 강제 처리하지 않습니다. 설치 후 반드시 다시 조회하세요. ND 계획도 저장 전/확정 후 미확인 상태를 재검증합니다.
- 룰셋에는 확정한 매핑표와 출처가 들어 있으며 엑셀 파일을 실행 중 다시 읽지 않습니다. 엑셀이 변경되면 새 룰셋을 만들어야 합니다. 룰셋 불러오기만으로 저장되지 않습니다.
- 설치 후 **모델을 다시 조회**하세요. 구버전 기록에는 배치 요소의 실제 소속 유형 ID가 없어서 적용이 차단됩니다. 저장 직전과 묶음 확정 후에 유형 ID와 재료 근거를 확인해 변했으면 저장하지 않습니다. 실제 층 재료·구조재료·가변층·우선순위는 수정하지 않습니다. 검토 요약에 항목별 변경 예정/이미 동일/확인 필요 개수를 표시합니다.

작성 형식: `Version: 2`, `Name`, 빈 `Rules`, `Kac` 필수. Kac는 Scope=유형(규칙의 기준), ManufacturerInfo, Company, MaterialPolicy=외측-상단-천장하단-단일재료, UnresolvedPolicy=기존값유지-확인필요, Classification(최대 5000개), Ifc(최대 200개), Sources를 가집니다. 선택 항목 InstanceFields는 0.1.7부터 6항목의 정확한 이름을 중복 없이 허용하며 생략 시 기존 유형 전용입니다. 기존 3항목 목록은 그대로 3항목만 적용됩니다. Classification은 Code/Kbims/Procurement/KbimsSource/ProcurementSource, Ifc는 Prefix/Value/Source를 사용합니다. 확정표 안의 중복 코드와 알 수 없는 속성은 거부합니다. 실행 코드나 임의 수식은 없습니다.

## 0.1.8 선택 정책 — 층 텍스트 정리

버전2 Kac에 `NormalizeFloorName: true`를 명시하면 기존 KAC 대상의 이름이 정확히 `층`인 텍스트 매개변수를 정리합니다. 배치 요소에도 적용하려면 `InstanceFields`에 `층`을 추가합니다. 생략/false인 기존 룰셋은 바뀌지 않습니다. 0.1.7 이하에서는 새 속성을 읽을 수 없으므로 먼저 프로그램을 업데이트합니다.

- `GL+6300_지상2층 → 지상2층`, `GL-3000_지하1층 → 지하1층`, `GL±0_지상1층 → 지상1층`. GL 대소문자, 소수 높이, 주변 공백도 허용합니다.
- 각 유형/요소 자신의 현재 원시 텍스트를 사용합니다. 같은 유형이라는 이유로 서로 다른 층을 통일하지 않습니다.
- 빈 값/값 없음은 그대로 둡니다. 레벨에서 값을 가져와 채우거나 실제 레벨 참조·위치·높이를 바꾸지 않습니다.
- 전체 값이 GL 높이 접두어(선택)+지상/지하+숫자+층 형식인 경우만 처리합니다. 옥탑·층 범위·복수층·다른 접두어/접미어는 추정하지 않고 확인 필요로 남깁니다.
- 동명 중복·실제 읽기전용·비텍스트 필드는 유지합니다. 수동 변경과 충돌하면 전체 보류하고 저장 직전 기존값도 재검증합니다. 다른 6항목 및 최신 KBIMS 상위행 보완 매핑은 그대로입니다.

## KAC 유형 정리 (룰셋 버전4, 프로그램 0.2.7 이상)

`Version: 4`, `Name: "정리 룰셋 이름"`, `Cleanup: true`의 선언형 파일입니다. Kac/Space/Rules와 혼합하지 않습니다. 등록 모델 전체 KAC-A-/KAC-S- 유형·배치 및 매스 작업세트 예외를 검토합니다. 실제 적용은 별도 확인을 거치며 미확인/중복 항목은 유지합니다. 정리 근거가 없는 이전 조회는 재조회해야 합니다. 구체적인 지원 범위와 보류 기준은 사용 안내의 ‘KAC 유형·작업세트 정리’를 확인하세요. 개인 업무 룰셋은 설치 ZIP에 포함하지 않고 별도로 전달합니다.

프로그램 0.3.9부터 선택적으로 `"PreserveWorksets": ["00_외장"]`을 추가할 수 있습니다. 현재 작업세트가 정확히 `00_외장`인 배치 요소는 작업세트만 유지하고 다른 정리 항목은 계속 검토합니다. 이 항목이 없는 기존 버전4 룰셋의 동작은 바뀌지 않습니다. 다른 작업세트 이름이나 다른 버전의 사용은 지원하지 않습니다. 이전 룰셋에서 만든 변경 목록은 제외하고 새 룰셋으로 다시 검토하세요.

## SP·SA 프로젝트 정보 (룰셋 버전3, SA는 프로그램 0.2.5 이상)

- 별도 `Space` 프로필. `Scope=프로젝트 정보`, `UnresolvedPolicy=건축물번호유지-확인필요`, 출처/원본 SHA-256 및 건물 표를 포함합니다. KAC/일반 규칙과 혼합할 수 없습니다. 원본 엑셀과 개인 확정표는 설치 ZIP에 넣지 않습니다.
- `Buildings`는 Airport, Number(엑셀 건물번호), Name(참고 건물명), ManagementCode, Ownership, SourceRow 및 선택적인 NameAliases(사용자가 확정한 파일명 건물명 별칭)입니다. 실행 코드는 받지 않으며 엑셀을 실행 중 재해석하지 않습니다. Number의 앞자리 0만 정규화하고 하위 번호는 구분합니다.
- 등록한 원본 경로의 `PUS|MWX|CJU-숫자(선택: -하위숫자)건물명-SP.rvt` 또는 `-SA.rvt`를 대상으로 합니다. 기존 버전3 룰셋 파일은 수정할 필요가 없습니다. 건물명 앞 구분자 밑줄/하이픈 및 파일명 대소문자를 허용합니다. 건물명 유사도나 파일명 중간 문자열로 추정하지 않습니다. `-SP`/`-SA` 뒤에 백업 번호/사용자 접미사가 있으면 제외합니다. 별칭은 같은 공항 안에서 건물명 전체가 일치할 때 번호보다 우선하며 공백·영문 대소문자만 정규화합니다.
- 프로젝트 정보의 유일한 텍스트 `공항코드`, `건축물번호`만 사용합니다. 건축물번호는 같은 공항 관리코드의 앞 3자 제거 + 하이픈 + 숫자 소유구분. 0은 유효합니다. 관리코드/소유구분 누락, 다른 공항 코드, 미등록/중복 건물번호는 공항코드만 준비하고 건축물번호 유지·확인 필요 안내를 남깁니다. 빈 셀은 위 행에서 상속하지 않습니다.
- 필드 부재·동명 중복·읽기전용·수동 충돌은 전체 보류합니다. 기존값/저장 직전 최신성 확인 및 명시적 최종 저장 절차를 그대로 사용합니다. 값이 이미 같아 변경 0개여도 확인 필요 안내는 남습니다.

### 0.3.0 선택 정책 — 건축물번호 누락 ND

버전3 `Space`에 `MissingBuildingNumberValue: "ND"`를 명시하면 **유일하게 연결한 건물 행**의 ManagementCode 또는 Ownership이 빈 문자열/공백일 때 건축물번호를 `ND`로 대체합니다. 기존 건축물번호도 덮어쓰며 변경 근거에 누락 항목과 원본 행을 기록합니다. 공항코드·정상값·확정 별칭은 기존 방식입니다. `0` 소유구분은 누락이 아닙니다. 미등록/중복 건물과 두 값 모두 비어 있지 않은 형식 오류는 계속 기존값 유지/확인 필요입니다. 읽기전용·필드 부재·모호성·수동 충돌 보호를 유지합니다. 생략/빈 문자열은 이전 유지 정책이며 ND 외 임의값/null은 거부합니다. 새 정책은 프로그램 0.3.0 이상에서만 읽을 수 있습니다. KAC 버전2의 7항목 룰셋과 혼합하지 않습니다.

### 0.3.2 선택 정책 — 자산번호

버전3 `Space`에 `MapAssetNumber: true`를 명시하면 프로젝트 정보의 유일한 텍스트 `자산번호`도 조회·입력합니다. 건물 행마다 `AssetNumber`(숫자만, 1~20자리)를 둡니다. 빈 문자열은 원본 누락이며 `MissingAssetNumberValue: "ND"`일 때만 `ND`로 대체하고(기존값도 덮어씀), 생략/빈 문자열이면 기존값 유지·확인 필요입니다. 숫자가 아닌 값, `MapAssetNumber` 없이 적힌 자산번호, ND 외 대체값은 룰셋 전체를 거부합니다. 미등록/중복 건물은 자산번호도 추정하지 않습니다. 0.3.1 이하 프로그램은 이 속성을 읽지 못합니다.

### 0.3.3 선택 정책 — 없는 자산번호 매개변수 추가

`MapAssetNumber: true`와 함께 `AddMissingAssetParameter: true`를 명시하면, 프로젝트 정보에 `자산번호`가 없는 모델에 대해 함께 조회한 모델들의 `자산번호`(프로젝트 정보·공유 매개변수·텍스트)가 하나의 GUID·그룹으로 일치할 때만 그 정의를 프로젝트 정보 인스턴스 매개변수로 추가하고 값을 입력합니다. 기준이 없거나 공유가 아니거나 정의가 여러 개이면 해당 모델의 자산번호만 확인 필요로 건너뜁니다(다른 항목은 적용). 같은 GUID·다른 이름, 수동 변경 충돌은 전체 보류합니다. Revit 적용 시 같은 GUID 공유 매개변수가 이미 있거나 같은 이름의 다른 매개변수가 있으면 추가하지 않습니다. `공항코드`·`건축물번호`에는 적용하지 않습니다. 0.3.2 이하 프로그램은 이 속성을 읽지 못합니다.

## 속성규격 매개변수 검사·정리 (룰셋 버전5, 프로그램 0.3.5 이상)

- 값이 아니라 **매개변수 정의**(이름·유형/인스턴스·데이터 유형·그룹·연결 카테고리)를 검사합니다. 다른 룰셋·직접 입력과 섞어 적용하지 않습니다.
- 형식: `Version: 5`, `Name`, 빈 `Rules`, `Spec` 필수. Spec은 Source, SourceSha256(원본 엑셀 SHA-256), MergeDuplicates, AddMissing, Parameters. 각 항목은 Name, Legacy(이전 이름 목록), Binding(`인스턴스`/`유형`), DataType(`문자`·`길이`·`면적`·`체적`·`예/아니요`), Group(`기타`·`문자`·`치수`·`ID 데이터`·`IFC 매개변수`·`일반`·`데이터`·`가시성`), AllCategories 또는 Categories(Revit `OST_` 카테고리 이름), ExcludeCategories(All일 때만), SourceRow.
- `AllCategories: true`는 그 모델에서 매개변수를 연결할 수 있는 모든 카테고리입니다. 빠진 카테고리만 추가하고 기존 연결은 빼지 않습니다.
- 중복 판정: 같은 이름 정의 여러 개, 띄어쓰기·대소문자만 다른 이름, Legacy 이름. 이전 이름이 다른 규격 이름과 같으면(예: 텍스트 `구조` ↔ 예/아니요 `구조`) 데이터 유형으로 구분합니다.
- 없는 매개변수는 AddMissing일 때 함께 조회한 다른 모델에서 같은 이름·데이터 유형 공유 매개변수 GUID가 가장 많이 쓰인 하나로 정해질 때만 추가합니다. 엑셀에는 GUID가 없으므로 기준 모델을 함께 조회하세요.
- 엑셀이 바뀌면 룰셋을 새로 만들어야 합니다. 실행 중 엑셀을 다시 읽지 않습니다.
- **삭제 전용(0.3.6)**: `RemoveOnly: true`(AddMissing·MergeDuplicates는 false). 각 항목의 Legacy 이름 정의를, 규격 이름 정의가 하나 있는 모델에서 카테고리가 Categories와 정확히 같을 때만 값 이동 없이 삭제합니다. 다른 검사·정리는 하지 않습니다.

## 버전1 상세 형식

- UTF-8 JSON, 최대 2MB. Version: 1, Name, Rules 필수. SampleOnly: true면 연습 데이터에서만 사용.
- 규칙마다 고유한 Name, Match, Set을 지정. 최대 500개 규칙, 규칙당 100개 입력값.
- Match.Scope: 유형, 인스턴스, 프로젝트 정보 중 하나. 유형/인스턴스는 Type 조건 필수.
- Match.TypeMatch: 일치(기본), 시작, 포함. 대소문자를 구분하며 와일드카드/정규식/실행 코드는 없음.
- Match.Model, Category, Family: 선택 사항. 조회된 모델 제목(확장자 없는 이름)·카테고리·패밀리에 정확히 일치. 지정된 조건은 모두 만족해야 함. 모델 제목이 같으면 해당 제목의 파일 모두 대상이므로 최종 목록에서 소속 파일 확인.
- Set: Name, DataType, Storage, Value 필수. 자료형은 추측하지 말고 실제 조회값의 식별자를 사용. Storage는 String, Integer, Double, ElementId.
- ParameterKey를 지정할 때는 guid:<공유 GUID> 또는 builtin:<음수 ID>만 허용. 다른 모델에 의미가 다른 id:는 금지. 지정 시 이름·자료형·저장형식·키가 모두 맞아야 함. 미지정 시 **각 소유 요소 안에서** 이름·자료형·저장형식이 유일한 항목만 연결. 모델 간 현재값 자동 복사와 달리 명시한 고정값을 입력하는 규칙임.
- Value는 문자열. 빈 문자열은 텍스트 지우기, 누락/null은 오류. 숫자 "25", 치수 "200 mm", 선택형은 해당 모델 선택 목록의 정확한 이름을 사용. 단위 숫자 해석은 실제 적용 시 Revit에서 재검증.
- 공유 GUID/자료형 등 룰셋 작성에 필요한 실제 메타데이터는 **연결 설정 · 작업 보관 → 작업 저장**의 조회 결과에서 확인 가능. 작업 파일에는 실제 프로젝트 정보가 있으므로 외부 공유 주의.

## 범위와 안전

룰셋은 **조회가 완료된 등록 파일 전체**를 대상으로 합니다. 목록의 검색어, 보이는 필드, 선택 행은 룰셋 범위를 제한하지 않습니다. 파일별로 다르게 적용하려면 룰셋 조건에 모델명을 명시하거나 대상 파일만 등록합니다.

버전1에서 조건에 맞는 대상이 없는 규칙은 미리보기 위에 표시합니다. 대상은 있으나 매개변수가 없거나 여러 개이거나 읽기 전용인 경우, 잘못된 입력값 또는 서로 다른 규칙/기존 변경값의 충돌은 **룰셋 전체를 보류**합니다. 기존 변경 목록을 지우거나 마지막 규칙으로 몰래 덮어쓰지 않습니다. 버전2의 미확인 항목 정책은 위 설명을 따릅니다.

동일한 값은 변경 목록에서 제외합니다. 불러온 결과에는 규칙 이름을 기록합니다. 변경 목록에서 원하지 않는 항목을 제외할 수 있습니다. 불러오기만으로 파일을 열어 수정하거나 저장하지 않습니다. 최종 저장 때 기존값·실제 권한·대상 식별자를 재검증하며 이전 버전의 중앙 동기화 안전장치를 그대로 사용합니다.

룰셋 자체는 중앙 동기화의 성공이나 Revit 네이티브 오류 부재를 보장하지 않습니다. 처음에는 별도 테스트 모델에서 검증하세요.
