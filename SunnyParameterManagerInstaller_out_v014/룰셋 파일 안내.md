# 룰셋 파일 안내

규칙은 프로그램 안에서 만들지 않습니다. 사용자와 대화로 정한 내용을 **.sunnyrules.json** 파일로 만들어 전달하고, 프로그램에서는 **RVT 파일 선택 → 룰셋 불러오기 → 변경 내용 확인 → RVT에 저장**만 수행합니다.

함께 들어 있는 **연습용.sunnyrules.json**은 **샘플로 연습하기**에서만 쓸 수 있고 실제 모델에는 적용할 수 없습니다. 샘플을 연 뒤 이 파일을 불러오면 두 샘플 파일의 업체명 36개가 어떻게 바뀔지 표시됩니다. 실제 저장은 비활성 상태입니다. 실무용 KAC 룰셋은 원본 엑셀과 별도로 전달하며 아래 버전2 설명을 따릅니다.

## KAC 건축·구조 룰셋 (버전2, 프로그램 0.1.4 이상)

- 유형명이 `KAC-A-영문2자숫자4자리` 또는 `KAC-S-영문2자숫자4자리`로 시작해야 합니다. 코드 뒤는 이름 끝 또는 밑줄/하이픈/공백입니다. 다른 공정·이름 형식은 제외합니다.
- **유형에 실제로 존재하는 텍스트 매개변수** 6개만 대상입니다. 인스턴스 값을 유형 값으로 대신 읽거나 매개변수를 새로 만들지 않습니다. 각 유형에서 이름이 유일하고 Revit 텍스트 자료형이어야 합니다.
- `다음으로 IFC로 내보내기`: IFC 표의 건축 구분에서 유형 코드별 첫 Ifc 이름. FA처럼 숫자 분류별로 값이 다르면 구체적인 접두어 우선. IFC 내보내기 파일 자체의 적합성 검증은 별도입니다.
- `제작정보`: KAC-v1.0. `업체명`: ND.
- `KBIMS-부위코드`, `조달청표준공사코드`: 엑셀 항목명으로 열을 찾고 영문 분류+4자리 코드를 정확히 연결합니다. 같은 코드에 다른 값이 있으면 위쪽에서 처음 실제로 적힌 값을 채택합니다. 빈칸은 지우기 명령이 아니며 상위 분류값을 임의로 상속하지 않습니다.
- `재료명`: 벽 외측층, 바닥·지붕 최상단층, 천장 최하단층 재료 이름에서 맨 앞 `KAC-`만 제거합니다. 막층도 건너뛰지 않습니다. 외측층이 미지정이면 안쪽층으로 대체하지 않습니다. 일반 유형은 지정/형상 재료가 하나일 때만 사용하며 여러 재료, 수직 복합벽, 미지정 재료는 확인 필요로 둡니다. 도장·인스턴스 재료로 외측을 추정하지 않습니다.
- 미확인/누락/읽기전용 항목은 **그 항목만 기존값 유지**, 검토 요약과 작업 기록에 구체적인 이유를 남깁니다. 이미 준비한 변경과 서로 다른 값을 요구하면 기존 변경을 보존하고 전체 보류합니다. 이 정책은 기존 버전1의 전체 보류 정책을 바꾸지 않습니다.
- 룰셋에는 확정한 매핑표와 출처가 들어 있으며 엑셀 파일을 실행 중 다시 읽지 않습니다. 엑셀이 변경되면 새 룰셋을 만들어야 합니다. 룰셋 불러오기만으로 저장되지 않습니다.
- 구버전 조회값에는 외측 재료 근거가 없습니다. 설치 후 **모델을 다시 조회**하세요. 저장 직전과 묶음 확정 후에 재료 근거를 확인해 변했으면 저장하지 않습니다. 실제 층 재료·구조재료·가변층·우선순위는 수정하지 않습니다.

작성 형식: `Version: 2`, `Name`, 빈 `Rules`, `Kac` 필수. Kac는 Scope=유형, ManufacturerInfo, Company, MaterialPolicy=외측-상단-천장하단-단일재료, UnresolvedPolicy=기존값유지-확인필요, Classification(최대 5000개), Ifc(최대 200개), Sources를 가집니다. Classification은 Code/Kbims/Procurement/KbimsSource/ProcurementSource, Ifc는 Prefix/Value/Source를 사용합니다. 확정표 안의 중복 코드와 알 수 없는 속성은 거부합니다. 실행 코드나 임의 수식은 없습니다.

## 버전1 형식 (사용자가 직접 편집할 필요 없음)

- UTF-8 JSON, 최대 2MB. Version: 1, Name, Rules 필수. SampleOnly: true면 연습 데이터에서만 사용.
- 규칙마다 고유한 Name, Match, Set을 지정. 최대 500개 규칙, 규칙당 100개 입력값.
- Match.Scope: 유형, 인스턴스, 프로젝트 정보 중 하나. 유형/인스턴스는 Type 조건 필수.
- Match.TypeMatch: 일치(기본), 시작, 포함. 대소문자를 구분하며 와일드카드/정규식/실행 코드는 없음.
- Match.Model, Category, Family: 선택 사항. 조회된 모델 제목(확장자 없는 이름)·카테고리·패밀리에 정확히 일치. 지정된 조건은 모두 만족해야 함. 모델 제목이 같으면 해당 제목의 파일 모두 대상이므로 최종 목록에서 소속 파일 확인.
- Set: Name, DataType, Storage, Value 필수. 자료형은 추측하지 말고 실제 조회값의 식별자를 사용. Storage는 String, Integer, Double, ElementId.
- ParameterKey를 지정할 때는 guid:<공유 GUID> 또는 builtin:<음수 ID>만 허용. 다른 모델에 의미가 다른 id:는 금지. 지정 시 이름·자료형·저장형식·키가 모두 맞아야 함. 미지정 시 **각 소유 요소 안에서** 이름·자료형·저장형식이 유일한 항목만 연결. 모델 간 현재값 자동 복사와 달리 명시한 고정값을 입력하는 규칙임.
- Value는 문자열. 빈 문자열은 텍스트 지우기, 누락/null은 오류. 숫자 "25", 치수 "200 mm", 선택형은 해당 모델 선택 목록의 정확한 이름을 사용. 단위 숫자 해석은 실제 적용 시 Revit에서 재검증.
- 공유 GUID/자료형 등 룰셋 작성에 필요한 실제 메타데이터는 **연결 설정 · 작업 보관 → 작업 저장**의 조회 결과에서 확인 가능. 작업 파일에는 실제 프로젝트 정보가 있으므로 외부 공유 주의.

## 범위와 안전

룰셋은 **조회가 완료된 등록 파일 전체**를 대상으로 합니다. 목록의 검색어, 보이는 필드, 선택 행은 룰셋 범위를 제한하지 않습니다. 파일별로 다르게 적용하려면 룰셋 조건에 모델명을 명시하거나 대상 파일만 등록합니다.

버전1에서 조건에 맞는 대상이 없는 규칙은 미리보기 위에 표시합니다. 대상은 있으나 매개변수가 없거나 여러 개이거나 읽기 전용인 경우, 잘못된 입력값 또는 서로 다른 규칙/기존 변경값의 충돌은 **룰셋 전체를 보류**합니다. 기존 변경 목록을 지우거나 마지막 규칙으로 몰래 덮어쓰지 않습니다. 버전2의 미확인 항목 정책은 위 설명을 따릅니다.

동일한 값은 변경 목록에서 제외합니다. 불러온 결과에는 규칙 이름을 기록합니다. 변경 목록에서 원하지 않는 항목을 제외할 수 있습니다. 불러오기만으로 파일을 열어 수정하거나 저장하지 않습니다. 최종 저장 때 기존값·실제 권한·대상 식별자를 재검증하며 이전 버전의 중앙 동기화 안전장치를 그대로 사용합니다.

룰셋 자체는 중앙 동기화의 성공이나 Revit 네이티브 오류 부재를 보장하지 않습니다. 처음에는 별도 테스트 모델에서 검증하세요.
