# Sunny 매개변수 관리자 0.2.8 — 테스트 버전

## 조회 중 파일 확인과 룰셋 선택 표시

- 조회 중에도 왼쪽 **선택한 파일** 목록을 휠 또는 스크롤바로 이동하여 파일명·진행 상태를 확인할 수 있습니다. 조회 대상을 바꾸거나 입력/저장하는 기능은 완료까지 잠깁니다.
- 룰셋을 불러오면 시작 화면의 초록색 **룰셋 선택 완료** 안내에서 이름을 확인하세요. 상단에도 이름이 계속 표시되고 버튼은 **룰셋 바꾸기**로 바뀝니다. 다음으로 RVT 파일을 선택하면 됩니다.
- 룰셋 선택은 준비 단계이며 실제 모델에 저장된 상태가 아닙니다. 룰셋 해제 또는 샘플 전환 시 선택 완료 표시도 사라집니다.

## KAC 유형·작업세트 정리

별도 전달한 버전4 정리 룰셋을 먼저 불러오고 RVT를 새로 조회하세요. 이전 전체 조회/기존 KAC 조회에는 총 두께·ID 데이터 구분 근거가 없어 재조회가 필요합니다. 기존 6개/7개 매개변수 룰셋과는 별도로 실행합니다.

- 등록 모델 전체의 KAC-A-/KAC-S- 유형(미배치 유형 포함)과 배치 요소가 대상입니다. 일람표/현재 화면의 검색 필터로 범위를 제한하지 않습니다. 링크 안쪽은 원본 RVT를 별도로 등록합니다.
- 유형명의 잘못된 구분자와 THK를 정리하고, 단일 T 두께 규격의 수치를 실제 총 두께(mm, 소수 셋째 자리까지)에 맞춥니다. 괄호 설명과 H/W 규격 등은 보존합니다. 복합 구조 전체 두께 또는 유일한 길이형 유형 두께 매개변수를 사용합니다. 가변/비균질 구조나 두께 미확인은 기존 수치를 유지하며 사유를 표시합니다.
- 배치 요소의 작업세트는 A→01_건축, S→02_구조, 매스는 접두어와 무관하게 09_매스로 지정합니다. 없는 작업세트는 만들지 않습니다.
- ID 데이터 그룹의 유일한 사용자 Yes/No 매개변수만 대상으로 건축/구조 중 해당 분야만 켜고 나머지를 끕니다. 동명 Revit 기본 속성은 제외합니다. 실제 룸 경계 기본 매개변수는 끄며 방/면적 변화가 발생할 수 있습니다.
- 내부편집의 구조 기둥/지붕/바닥/벽은 각각 IfcColumn/IfcRoof/IfcSlab/IfcWall로 정리합니다. 일반 모델 등 용도 불명 카테고리는 기존 IFC를 유지합니다.
- 변경 검토에 모델·대상·항목·기존 값·바뀔 값·근거가 나타납니다. 상단 안내와 처리 결과에는 보류/유지 사유가 기록됩니다. 원하지 않는 변경은 목록에서 제외하세요. 다른 직접 편집과 섞지 않고 최종 확인 후에만 저장합니다.
- 적용 직전 새 로컬에서 규칙·두께·작업세트·원래 값을 다시 확인하고, 확정 후 승인한 이름/값을 검증합니다. 오류 시 해당 모델 묶음을 취소합니다. 여러 중앙모델을 한꺼번에 되돌릴 수는 없습니다. 먼저 별도 테스트 중앙에서 검증하세요.

Sunny Tools 리본과 별도로 실행하는 Windows 프로그램입니다.

**룰셋 먼저 불러오기 → RVT 파일 선택 → 필요한 값 조회 → 변경 내용 확인 → RVT에 저장**

## 필요한 항목만 빠르게 조회하기

1. 첫 화면의 **룰셋 먼저 불러오기**에서 기존 업무 룰셋을 선택합니다. 룰셋 파일 수정은 필요 없습니다.
2. 상단에 룰셋 이름과 조회할 매개변수가 표시됩니다. **RVT 파일 선택** 또는 **폴더에서 RVT 찾기**로 모델을 추가합니다.
3. 해당 항목과 판단 근거만 읽고 등록 파일이 모두 조회되면 변경 검토를 준비합니다. **룰셋 변경 검토**로 다시 평가할 수도 있습니다. 읽거나 검토하는 것만으로 RVT는 변경되지 않습니다.
4. 기존 값·바뀔 값·확인 필요 사유를 확인하고 **RVT에 저장 · 중앙 동기화**에서 별도로 승인합니다.

- 공항코드·건축물번호 룰셋은 프로젝트 정보만 조회합니다(SP·SA 지원). KAC 룰셋은 유형·인스턴스의 지정 필드, 실제 유형 연결, 외측 재료 근거를 조회합니다. ‘층’ 정리 옵션이 있으면 기존 층 값도 포함합니다.
- 선택하지 않은 매개변수는 목록에 없습니다. 이것은 빈 값이나 재료 없음이 아닙니다. 필요한 항목이 다른 룰셋으로 바꾸면 **파일 관리 → 다시 조회**하세요. 기존 변경 예정은 자동으로 지우지 않으므로 먼저 적용하거나 작업 저장 후 정리해야 합니다.
- 룰셋 없이 파일을 선택하면 전체 조회입니다. **연결 설정 · 작업 보관 → 룰셋 해제 · 전체 조회로 전환** 후 다시 조회하면 뷰·시트 등 전체 항목을 가져옵니다. 전환 버튼만 누르는 것은 기존 조회를 바꾸지 않습니다.
- 작업 파일에는 준비한 룰셋과 각 파일의 조회 범위도 함께 저장됩니다. 업무 정보가 포함되므로 안전하게 보관하세요.
- 조회값 생성·전송·화면 메모리를 줄이는 기능입니다. Revit이 RVT 자체를 여는 시간과 메모리는 여전히 필요하며, 메모리 부족을 완전히 방지하지는 않습니다.

규칙은 대화로 정해 파일로 전달받으면 됩니다. 프로그램 안에서 규칙을 작성할 필요는 없습니다. KAC 업무용 룰셋은 별도 전달 파일을 사용합니다. 룰셋이 없어도 행을 선택해 값을 직접 입력할 수 있습니다.

## 파일 하나의 조회가 실패했을 때

- 실패 파일 이름·원인·남은 개수와 **나머지 파일을 계속 조회할까요?** 확인창이 나옵니다. **예**는 해당 실패 파일을 건너뛰고 다음 파일로, **아니요**는 이번 조회만 멈춥니다. 완료된 결과와 변경 예정은 지우지 않습니다.
- 나중에 **파일 관리 → 미조회 파일 계속 조회**를 누르면 아직 시도하지 않은 파일만 읽습니다. 실패한 파일을 자동 반복하지 않습니다. 실패 파일은 원인을 확인한 뒤 ‘다시 조회’하거나 목록에서 제외하세요. 제외는 원본 RVT 삭제가 아닙니다. 실패 파일이 목록에 남아 있으면 전체 룰셋 준비는 계속 차단됩니다.
- 조회 중 메모리가 부족한 경우, 작업용 Revit에 문서가 남아 있지 않음을 확인한 때만 승인 후 정상 종료·새 연결을 진행합니다. 연결에 시간이 걸릴 수 있습니다. 강제 종료하지 않습니다.
- 문서가 남았거나 저장·동기화 결과를 확인할 수 없는 상태는 이 팝업으로 우회하지 않습니다. 처리 결과와 작업용 Revit을 확인하세요. 조회 도중 응답이 사라졌는데 프로세스가 살아 있는 경우도 임의로 다음 파일을 열지 않습니다.
- 결과를 큰 문자열로 한 번 더 만들지 않고, 진행 기록에 조회 결과를 중복 저장하지 않습니다. 0.2.6부터 룰셋 우선 선택 조회도 지원하지만 모델 자체의 메모리나 누적 조회 결과 사용량까지 없애는 것은 아닙니다.
- 구버전에서 이미 잠긴 작업에는 새 기능이 소급 적용되지 않습니다. 미적용 변경은 ‘작업 저장’으로 보관하고 작업용 Revit의 상태를 확인한 뒤 종료·업데이트하세요.

## 선택 모델의 링크·가져오기를 완전히 없애려면

1. 실제 RVT 파일들을 등록합니다. 준비한 매개변수 변경이 있다면 먼저 적용하거나 ‘작업 저장’ 후 변경 목록을 정리합니다.
2. 왼쪽 하단 **링크·가져오기 완전 제거…**를 누릅니다.
3. 삭제할 모델만 체크하고 **삭제 영향 검사**를 누릅니다. 체크하지 않은 모델은 처리하지 않습니다. 검사만으로 원본 파일을 저장하지 않습니다.
4. 삭제 대상과 함께 삭제되는 종속 요소 목록을 확인합니다. 태그·치수 등 종속 요소가 있으면 추가 동의 체크가 필요합니다.
5. 하단에 **모두 삭제**를 정확히 입력하고 빨간 **완전 삭제 · 저장 · 중앙 동기화** 버튼을 누른 뒤 최종 확인창에서 승인합니다.
6. 모델별 처리 기록과 삭제 전 백업 경로를 확인합니다. 매개변수 작업을 이어가려면 RVT를 다시 조회하세요.

**언로드가 아닙니다.** Revit 링크, CAD 링크/가져오기, 포인트 클라우드, 이미지·PDF, 조정 모델(NWC/NWD 등), 지형 링크, DWF 마크업의 정의와 배치를 모델에서 삭제합니다. 화면에 보이지 않는 항목, 고정 항목, 배치가 없는 정의도 대상입니다. 중첩 링크는 상위 링크 제거 영향으로 확인하며 중첩 원본 RVT 자체를 열어 고치지 않습니다.

**외부 원본 RVT/CAD/PDF/포인트 클라우드 파일 자체는 삭제하지 않습니다.** 키노트·조합코드·재료 텍스처/데칼 등의 설정 참조와 로드 패밀리 내부는 제외합니다. 가져오기를 이미 분해해 일반 Revit 요소가 된 형상은 출처를 추정하여 삭제하지 않습니다. 알 수 없는 외부 참조가 있거나 Revit이 일부 정의의 삭제를 거부하면 해당 모델 전체를 보류합니다. 모두 지웠다고 표시하며 일부를 남기지 않습니다.

일반파일/기존 로컬은 삭제 전 파일 백업, 중앙모델은 새 로컬을 만든 직후 삭제 전 사본을 별도 보관합니다. 이 사본은 자동 복구 버튼이나 중앙 서버 백업이 아닙니다. 복원은 다른 사람의 후속 작업 여부와 중앙 상태를 먼저 확인해야 하며 백업을 중앙에 임의 덮어쓰면 안 됩니다. 기존 로컬을 선택하면 그 파일의 다른 미동기화 작업도 함께 동기화됩니다.

여러 모델은 순서대로 저장합니다. 한 모델에서 실패하면 나머지는 중단하되 이미 성공한 앞 모델은 그대로입니다. **반영 여부 확인 필요**라면 재실행하지 말고 작업용 Revit·복구 파일·중앙 상태를 확인하세요. 운영 모델에 바로 실행하지 말고 복사한 테스트 모델에서 링크 관리 목록과 도면 영향을 먼저 확인하세요.

## 뷰 구분 등 뷰·시트 값을 바꾸려면

**0.2.2 설치 → RVT 다시 조회 → 대상에서 뷰 또는 시트 → 수정할 항목 검색/선택 → 행 선택 → 값 입력 → 변경 내용 확인 → 저장** 순서입니다. 이전 조회 기록을 불러오기만 하면 새 뷰 항목이 생기지 않습니다. 기존 미적용 변경은 먼저 작업 저장으로 보관한 후 정리하세요.

평면·천장평면·입면·단면·상세·드래프팅·범례·일람표·3D 뷰를 실제 이름으로 표시합니다. 시트는 번호와 이름을 함께 표시합니다. Revit에서 화면에 열려 있지 않은 뷰도 포함합니다. 대상이 ‘유형’인 상태에서는 뷰가 보이지 않으므로 **뷰/시트/전체 범위** 중에 선택하세요. 선택한 매개변수가 실제 존재하는 대상만 표시됩니다.

`뷰구분-1`처럼 검색해도 `뷰 구분-1`을 찾습니다. 검색 결과에서 실제 항목을 선택하세요. 똑같은 뷰 유형을 사용하는 여러 뷰도 각각 선택한 뷰에만 입력합니다. **뷰 템플릿 자체와 내부 시스템 뷰는 제외**하며, 실제 읽기전용 또는 템플릿이 제어하는 값은 이유를 표시하고 수정하지 않습니다. 템플릿을 자동 해제하지 않습니다. 다른 파일의 같은 이름 뷰·시트로 자동 복사는 하지 않으며 직접 입력을 사용합니다. 기존 KAC·공간 룰셋의 적용 범위는 바뀌지 않습니다.

## 같은 파일에서 적용 실패가 반복될 때

0.2.0은 오류 내용을 숨기거나 형상 검사를 건너뛰지 않습니다. 처리 결과에서 Revit의 실제 오류와 관련 요소 번호, 유형 정보가 달라진 경우 적용 전후 식별자를 확인하세요. 형상 오류가 발생하면 오류 창에서 결합 해제·삭제를 선택했더라도 매개변수 작업 전체를 저장 전에 취소합니다. 일반 경고만 있는 작업은 이 이유로 차단하지 않습니다.

- **이번 변경 미저장**: 원본에서 문제 요소를 검토한 뒤 ‘다시 조회’를 누릅니다. 확인 창에서 동의하면 실패 파일의 미적용 변경만 비우고 다시 읽습니다. 필요한 변경 목록은 먼저 ‘작업 저장’으로 보관하세요. 다른 파일의 변경 예정은 유지합니다.
- **반영 여부 확인 필요**: 저장/동기화가 어디까지 되었는지 먼저 확인하세요. 작업용 Revit과 복구 로컬을 닫거나 같은 작업을 재실행하지 마세요. 이 상태에서는 재조회 초기화도 차단합니다.
- 실패한 조회값의 재적용은 차단합니다. 다시 조회한 후 룰셋을 새로 불러와 검토하세요. 원본 형상 문제를 고치지 않고 재조회만 하면 다시 실패할 수 있습니다.
- 창 제목의 **0.2.8** 표시로 실제 실행 버전을 확인하세요. 이 버전의 실제 사용자 모델 저장/동기화는 아직 검증하지 않았습니다.

## 여러 폴더에서 파일명으로 찾아 추가하기

1. **폴더에서 RVT 찾기**를 누릅니다.
2. **폴더 추가 (여러 개 선택)**에서 Ctrl/Shift로 폴더를 선택하세요. 다른 위치의 폴더는 버튼을 다시 눌러 이어서 추가할 수 있습니다.
3. **파일명에 포함할 문자열**에 `-SP`, `MWX`, `여객터미널`처럼 찾을 내용을 넣고 **파일 찾기**를 누릅니다. 영문 대소문자는 구분하지 않고, 입력한 전체 문자열을 그대로 포함하는 파일명만 찾습니다. 쉼표나 별표로 여러 조건을 표현하는 방식은 아닙니다.
4. 후보의 파일명·전체 경로를 확인하고 필요 없는 항목은 체크를 해제합니다. **체크한 파일 추가**를 누르면 새로 추가한 파일만 Revit에서 순서대로 조회합니다. 검색만으로 RVT를 열거나 수정하지 않습니다.

기본값은 **하위 폴더 포함 / 백업 제외**입니다. `.0001.rvt` 형식과 `_backup`으로 끝나는 폴더를 제외하며, 옵션을 끄면 포함할 수 있습니다. 같은 경로·이미 등록된 파일은 중복 추가하지 않지만, 이름이 같고 경로가 다른 파일은 구분해 표시합니다. 중앙과 로컬이 같은 모델인지 여부는 기존 조회 단계에서 다시 검증합니다.

접근 불가·연결 폴더 등 검색하지 못한 경로는 결과에 표시하고 후보 추가 전에 확인합니다. 연결 경로(재분석 지점)는 따라가지 않습니다. 검색 범위가 20만 항목을 넘으면 범위를 좁히도록 중단합니다. **검색 중지**는 네트워크 경로의 응답 대기가 끝난 뒤 처리될 수 있습니다. 기존 파일의 변경 예정은 새 파일 추가 때문에 지워지지 않습니다.

## 설치하고 연습하기

1. 열린 작업을 저장하고 Revit과 매개변수 관리자를 모두 종료합니다.
2. **SunnyParameterManager_Installer_v.0.2.8.zip** 전체를 풀고 **SunnyTools_Install.exe**를 실행합니다. 옆의 ParameterManager 폴더를 지우지 마세요.
3. 바탕화면의 **Sunny 매개변수 관리자**를 실행합니다.
4. **먼저 샘플로 연습하기 → ② 룰셋 불러오기 → 연습용.sunnyrules.json**을 선택하세요. 업체명 36개의 변경 전·후를 볼 수 있습니다. 샘플에서는 실제 저장이 차단됩니다.

필수: Windows x64, 설치·인증된 Revit 2026, .NET 8 Desktop Runtime x64. Revit 2026.4 API 기준 빌드입니다. 다른 Revit 연도, Revit Server/ACC, 자동 업그레이드, 분리 모델은 지원하지 않습니다. 일반 파일 경로·공유폴더/UNC RVT를 지원합니다.

설치기는 기존 Sunny Tools를 바꾸지 않고 별도 연결 모듈만 등록합니다. .NET 런타임이 없으면 [Microsoft 공식 다운로드](https://dotnet.microsoft.com/download/dotnet/8.0)의 **.NET Desktop Runtime / Windows x64**를 설치하세요.

## 실제 파일 사용

**0.2.5부터 기존 공간파일 룰셋으로 SA 건축파일에도 적용할 수 있습니다.** 룰셋 파일 수정 없이 기존 버전3 파일을 그대로 불러오세요. 프로젝트 정보의 `공항코드`, `건축물번호`만 수정합니다. 파일명은 `공항코드-건물번호건물명-SP.rvt` 또는 `공항코드-건물번호건물명-SA.rvt` 형태로 확인합니다. 공항은 PUS/MWX/CJU이며 건물번호 15와 15-1은 서로 다릅니다. SP·SA 외 접미사, 백업 번호나 사용자 접미사가 붙은 파일은 자동 추정하지 않습니다. 로컬 이름이 다른 경우 원래 이름의 중앙파일을 선택하세요. 건물명은 표기가 달라도 공항+번호로 찾되 최종 변경 목록의 소속 모델을 반드시 확인하세요. 사용자가 명시한 같은 공항의 건물명 별칭은 번호보다 우선하며 연결 근거를 요약에 표시합니다.

관리코드 또는 소유구분 숫자가 없거나 건물번호가 미등록/중복이면 **공항코드만 입력, 건축물번호 기존값 유지, 확인 필요 안내**입니다. 소유구분 0은 정상 값입니다. 필드 자체가 없거나 동명 중복·읽기전용·수동 변경 충돌이면 전체를 보류합니다. 프로젝트 매개변수를 새로 만들거나 유형/인스턴스의 동명 값에 대신 쓰지 않습니다. 기존 KAC 룰셋과 혼합하지 말고 공간파일용 파일을 별도로 불러오세요.

0.1.8의 새 7항목 룰셋은 기존 KAC 대상의 **층 텍스트**를 정리합니다. `GL+6300_지상2층 → 지상2층`, `GL-3000_지하1층 → 지하1층`. 유형·각 배치 요소의 현재 값을 각각 사용하며 빈 값은 채우지 않습니다. 실제 레벨·요소 높이/위치는 바꾸지 않습니다. 여러 층·옥탑 등 인식하지 못하는 표기는 유지하고 확인 필요로 표시합니다. 기존 룰셋은 이 기능이 자동으로 켜지지 않습니다. **0.1.8 설치 → RVT 새 조회 → 별도 전달한 7항목 룰셋 불러오기 → 변경 내용 확인 → 저장** 순서입니다.


0.1.7부터 **유형인스턴스모두_ND 룰셋**은 6개 항목 모두 유형/인스턴스 매개변수를 확인합니다. 유형에 없고 배치 요소에만 있는 KBIMS-부위코드·조달청표준공사코드·제작정보도 해당 요소의 실제 소속 유형 코드로 입력합니다. 양쪽에 있으면 양쪽을 각각 검토하며, 매개변수 설정 자체는 바꾸지 않습니다. **새 버전 설치 → 모델 새로 조회 → 새 룰셋 불러오기** 순서로 사용하세요. 기존 룰셋은 자동으로 범위를 넓히지 않습니다.

재료미확인ND 정책은 0.1.6과 같습니다. 기존 KAC 대상에서 정상 조회했으나 재료를 확정할 수 없는 경우 재료명만 ND로 바꾸며 기존 수동값도 교체될 수 있습니다. KBIMS/조달청 분류표 빈칸·미등록 코드에는 ND나 상위 분류값을 임의로 넣지 않습니다. 실제 읽기전용·필드 누락·동명 중복은 사유를 표시하고 유지합니다.

0.1.5는 실제 IFC 유형 필드 연결과 재료명·업체명 인스턴스 누락을 수정했습니다. **설치 후 모델을 새로 조회한 뒤 새 KAC 룰셋을 불러오세요.** 새 룰셋은 유형 기준 재료명·업체명 ND를 같은 유형의 모든 배치 요소에 넣고 IFC는 유형과 개별 요소 둘 다 엑셀 기준으로 맞춥니다. 개별 요소의 기존 IFC 지정값도 변경 대상입니다. 매개변수의 유형/인스턴스 설정 자체, IFC 내보내기 여부와 미리 정의된 유형은 바꾸지 않습니다.

6항목별 ‘변경 예정 / 이미 동일 / 확인 필요’ 개수를 검토하세요. 외측 불명·미지정 재료·읽기 전용은 기존값을 유지하며 이유를 표시합니다. 구버전 조회값에는 실제 소속 유형 ID가 없어 배치 요소 적용을 차단하므로 기존 작업을 불러오기만 해서는 안 됩니다. 새 룰셋만 불러와도 저장되지는 않습니다. 기존 룰셋의 유형 전용 범위는 그대로 유지합니다.

0.1.2에서는 일반 경로의 중앙/로컬 RVT 조회 중 “The current document is a file-based model.”로 중단되던 오류를 수정했습니다. 업데이트 후 RVT를 새로 선택해 조회하세요. 이전 버전에서 저장한 작업 기록은 새로 조회한 값으로 변경 내용을 다시 준비해야 합니다. 기존 변경 예정 목록이 있다면 작업 저장으로 별도 보관한 뒤 진행하세요.

1. **① RVT 파일 선택**에서 별도 테스트 모델을 고릅니다. 작업용 Revit 연결과 읽기가 자동으로 이어집니다. 처음에는 몇 분 걸릴 수 있습니다. 로그인·애드인 허용 창이 뜨면 확인하세요. 링크 모델도 수정하려면 해당 원본 RVT를 함께 선택합니다. 링크 내부를 자동으로 훑지는 않습니다.
2. **② 룰셋 불러오기**에서 전달받은 파일을 선택합니다. 모든 등록 파일을 대상으로 변경 예정 목록을 만듭니다. 검색/행 선택은 룰셋 범위를 제한하지 않습니다. 읽지 못한 파일은 제외하거나 다시 읽어야 합니다.
3. **변경 내용 확인**에서 기존 값·바뀔 값·소속 파일을 보고 **RVT에 저장 · 중앙 동기화**를 누릅니다. 마지막 확인창에서 승인해야 실제 반영됩니다. 처리 결과에서 성공/실패를 확인하세요.

**직접 입력할 때:** 대상과 수정할 항목 선택 → 행 선택 → 바꿀 값 입력 → **선택한 N개에 입력 → ③ 변경 내용 확인**. Ctrl/Shift 다중 선택, 전체 선택, 열 정렬/너비 조절을 지원합니다. 검색하거나 선택을 해제해도 이미 준비한 변경은 남습니다. 취소하려면 변경 내용 확인 탭에서 제외하세요.

**매개변수가 많을 때:** ‘수정할 항목’ 아래 **매개변수 검색…** 칸에 ‘재료’, ‘업체’, ‘ifc’처럼 이름 일부를 입력하고 아래 목록에서 고르세요. 입력할 때마다 후보와 검색 개수가 바뀝니다. 영문 대소문자와 앞뒤 공백은 무시합니다. 검색 결과와 별도로 현재 선택은 목록 맨 위에 남으며, 검색만으로 행 선택·입력값·변경 예정은 바뀌지 않습니다. **×**를 누르면 전체 후보로 돌아갑니다. 오른쪽 ‘이름·현재 값 검색’은 요소/유형/값을 찾는 별도 검색입니다.

연결 경로와 작업 저장은 **연결 설정 · 작업 보관**, 재조회와 파일 제외는 **파일 관리**에 있습니다. 룰셋 작성자를 위한 상세 내용은 동봉한 **룰셋 파일 안내.md**에 있습니다.

## 중앙모델과 로컬

대상 RVT를 미리 열 필요는 없습니다. 다만 설치·인증된 Revit 엔진이 필요하고 전용 Revit 프로세스를 자동 시작합니다.

중앙파일은 새 작업용 로컬을 만들어 수정·동기화합니다. 기존 로컬은 **그 로컬에 저장된 다른 미동기화 변경도 함께 동기화**됩니다. 다른 사람의 로컬은 열지 않습니다. 가급적 중앙파일을 등록하세요. 다른 사용자의 로컬파일은 자동으로 덮어쓰지 않으며 각 사용자가 최신 내용 가져오기를 해야 합니다.

작업용 Revit 창에 별도로 파일을 열지 마세요. 다른 Revit에서 같은 파일을 저장하거나 동시에 편집 중이면 충돌·소유권 때문에 실패할 수 있습니다. 소유권을 강제로 빼앗지 않습니다. 작업 후 **연결 설정 · 작업 보관 → 작업용 Revit 종료**로 빈 프로세스에 종료를 요청할 수 있습니다. 관리자를 닫아도 Revit을 강제 종료하지 않습니다.

## 다른 파일에서 값 가져오기

왼쪽 **다른 파일에서 값 가져오기**를 펼쳐 기준 파일을 지정합니다. 값을 받을 다른 모델의 행을 선택하고 **선택한 행에 값 가져오기**를 누릅니다.

- 카테고리·패밀리·유형이 같은 대상만 연결합니다. 공유 매개변수는 GUID, 기본 매개변수는 기본 식별자로 연결합니다.
- 공유 GUID가 없는 일반 매개변수는 **일반 매개변수도 이름으로 연결**을 체크해야 같은 이름·자료형·범위의 유일한 항목으로 연결합니다. 다른 공유 GUID를 이름으로 연결하지 않습니다.
- 인스턴스는 유형명이 같다고 같은 요소로 추정하지 않습니다. 직접 일괄 입력하거나 명시적인 인스턴스 룰셋을 사용하세요.
- 기준 파일의 조회 당시 현재 값을 복사합니다. 아직 저장하지 않은 변경 예정 값은 복사하지 않습니다.

## 지원 / 제한

- 텍스트, 정수, 숫자, 단위 숫자, 예/아니요, 재료 참조, 사용자 작업세트 선택. 실제 매개변수 자료형에 맞게 처리합니다.
- 텍스트를 비워 입력하면 값을 지웁니다. 숫자/선택 항목은 빈 값으로 지우지 않습니다. 치수는 "200 mm"처럼 단위를 함께 입력하세요.
- IFC 내보내기 관련 텍스트를 입력할 수 있지만 IFC 스키마나 최종 IFC 결과는 검증하지 않습니다.
- 수식·실제 읽기 전용·미지원 참조/열거값은 수정하지 않습니다. 매개변수 생성·바인딩·형상 추가는 하지 않습니다.
- 뷰·시트의 실제 매개변수 직접 입력은 지원합니다. 일람표 뷰도 해당 뷰의 매개변수를 읽는 것이며 일람표 셀/행 대응 편집은 아닙니다.
- 일람표 행 대응, 엑셀 직접 가져오기, 프로그램 안에서 규칙 작성, 예약 실행은 지원하지 않습니다.

## 안전과 복구

조회/룰셋 불러오기만으로 RVT를 수정하지 않습니다. 실제 적용 직전에 문서 식별자·요소·매개변수·기존 원시값·자료형·단위·권한을 확인하고 달라졌으면 덮어쓰지 않습니다. 일반파일/기존 로컬은 변경 전 백업을 만듭니다. 중앙의 새 작업용 로컬 보존은 중앙 서버 백업을 대체하지 않습니다.

여러 모델 전체를 한 번에 되돌릴 수는 없습니다. 앞 모델이 성공하고 뒤 모델이 실패하면 앞 모델 변경은 남습니다. 저장/동기화 실패와 응답 손실은 자동 재시도하지 않습니다. **반영 여부 확인 필요**가 나오면 전용 Revit과 로컬을 그대로 두고 실제 중앙 값과 기록부터 확인하세요. 소유권을 일괄 반납하지 않으므로 필요한 소유권 반납도 확인하세요.

**작업 저장**은 조회값과 변경 예정 목록을 .spm.json으로 보관합니다. 이 파일과 %LOCALAPPDATA%/SunnyTools/ParameterManager/Sessions 기록에는 모델 경로·매개변수 값이 있으므로 외부 공유에 주의하세요. 로컬·백업은 자동 삭제하지 않습니다. 중앙 반영/복구 확인 후 사용자가 정리할 수 있습니다.

400개 값·룰셋·실제 화면 자동 검사, 66개 적용 흐름·22개 재료 리더·23개 매개변수 리더·25개 링크 삭제 API 대역 검사를 수행했습니다. **수정본의 실제 사용자 RVT 조회·삭제·저장·중앙 동기화는 아직 검증하지 않았습니다.** 운영 모델 전체에 바로 적용하지 말고 별도 테스트 모델에서 확인하세요. Revit 네이티브 오류 부재를 보증하지 않습니다.
